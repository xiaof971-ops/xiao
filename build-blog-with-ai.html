和 AI 协作，一个下午搭好这个博客

你现在看到的这个博客，从第一行代码到绑定域名上线，一个下午搞定。协作方式很简单：我负责提需求和拍板，AI 负责写码、查资料、打包部署。这篇记录一下过程中的分工和心得。

整个链路长什么样

没有用任何建站平台，就是最朴素的三件套：纯 HTML + CSS + 少量原生 JS，部署在静态托管上，再挂上自己的域名。好处是无依赖、加载快、想改哪里改哪里。

meworld-blog/
├── index.html        # 首页
├── about.html        # 关于
├── archive.html      # 归档
├── tags.html         # 标签
├── posts/            # 文章
├── style.css     # 全站样式
├── site.js        # 交互脚本
└── sitemap.xml 等    # SEO 文件

哪些事交给了 AI

  • 写代码。整站样式、交互脚本、页面结构，描述清楚需求后直接生成，质量超出预期。
  • 查资料。部署方式对比、DNS 配置细节、报错排查（比如上传时超过 2MB 限制的坑），AI 直接给出结论和依据。
  • 做重复劳动。生成 RSS、sitemap、结构化数据这类机械但容易出错的东西，AI 又快又稳。

哪些事还得自己拍板

  • 说什么话。博客的语气、定位、写什么不写什么——AI 能模仿，但不能替你决定你是谁。
  • 审美取舍。AI 给的方案永远是"都行"，但"喜欢哪个"只有自己知道。来回改了三轮配色，最后拍板深色杂志风。
  • 发布的勇气。代码可以一直打磨，但"今天就上线"这个决定，只能自己按。

一句总结

AI 把"实现的成本"降到了接近零，于是"决定做什么"变成了唯一重要的事。这大概是 2026 年个人建站最大的变化：门槛不在技术，在于你有没有想清楚要表达什么。
